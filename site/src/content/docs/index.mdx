```bash
npm install parapdf
```

```tsx
import { PdfDocument, PdfViewer } from "parapdf";

export function App() {
  return (
    <PdfDocument source="/manual.pdf">
      <PdfViewer style={{ height: "100vh" }} />
    </PdfDocument>
  );
}
```

That is all the setup: ParaPDF ships pdf.js, its worker, and the files it
loads on demand, and your bundler serves them from your application's origin.

<CardGrid>
  <Card title="React stays out of the hot path" icon="rocket">
    Scrolling and zooming commit no React state per frame. React renders only
    when the set of mounted pages or the current page changes, and pixels
    never go through React: the renderer owns each page's canvases.
  </Card>
  <Card title="Only what is near the viewport exists" icon="document">
    Pages outside a small window unmount. Each page draws a quick base first
    and full resolution once scrolling settles, within pixel budgets you can
    set, and a page you come back to shows the canvases it kept.
  </Card>
  <Card title="One document, many views" icon="open-book">
    A `PdfDocument` opens a document once; any number of `PdfViewer`s and
    thumbnail lists show it, each with its own scroll position, zoom,
    rotation, and layout.
  </Card>
  <Card title="What a document viewer does" icon="pencil">
    Selectable text in a tagged PDF's structure, whole-document search, links
    and the outline with back and forward, fillable forms, annotations,
    layers, attachments, printing, and encrypted documents. Features load
    only when you use them.
  </Card>
</CardGrid>

ParaPDF is at 0.x: its API may change in any minor release until 1.0. The
[changelog](https://github.com/yhay81/parapdf/blob/main/CHANGELOG.md) lists
the releases, and [Performance](/about/performance/) the measurements behind
the design, losses included.
