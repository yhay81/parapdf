With `<PdfViewer forms />`, form fields become inputs, check boxes,
radio buttons, and lists the reader can fill in; without it, they show as the
PDF draws them. The option is live: turning it on or off needs no remount,
and the forms code loads only when it is set. What the reader types belongs
to the document, shared by its viewers, and a page keeps its values when it
unmounts and mounts again.

## Saving and printing

- `save(viewer)` resolves to the PDF's bytes with the values and the
  annotations created written in, and `download(viewer, filename?)` hands
  them to the browser as a download, named after the document's URL by
  default.
- `print(viewer, { resolution, onProgress, signal })` draws every page for
  printing, the typed values and the annotations created included, with the
  layers the viewer shows, at 150 dpi by default, and opens the
  browser's print dialog with only those pages. A new print request stops the
  previous job; that job resolves without opening another dialog.

## Reading and filling the form

```tsx
import { getFormFields, setFormValues, useFormChange, type Viewer } from "parapdf";

function FormSync({ viewer, onChange }: { viewer: Viewer; onChange: (name: string, value: unknown) => void }) {
  // Each value the reader enters, as they type.
  useFormChange(viewer, ({ name, value }) => onChange(name, value));
  const fill = async () => {
    const fields = await getFormFields(viewer);
    console.log(fields.map(({ name, type, value }) => [name, type, value]));
    await setFormValues(viewer, { name: "Ada Lovelace", agree: true, size: "large" });
  };
  return <button type="button" onClick={fill}>Fill in</button>;
}
```

- `getFormFields(viewer)` resolves to every field (`FormField`): its
  qualified `name`, `type` (`"text"`, `"checkbox"`, `"radio"`, `"combobox"`,
  `"listbox"`, `"button"`, or `"signature"`), current `value`,
  `defaultValue`, `readOnly`, `required`, `multiple`, the `options` of a
  list, the `exportValues` that check its boxes, and its `widgets`, each a
  page and a rectangle in PDF points. A value is text, the export value of
  the checked box or radio button (`"Off"` for none), or the selected
  options' export values, an array for a list that takes several.
- `setFormValues(viewer, values)` sets fields by name, `true` and `false`
  checking the first box or none, and resolves to the names it set. The
  fields shown show the values, and `save()` and `print()` include them; it
  is not heard as the reader's input.
- `useFormChange(viewer, listener)` hears `{ name, value }` for each value
  the reader enters, with `forms` on.
- `useFormFields()` gives the fields of the nearest `PdfDocument`'s document
  with their values as first read. It suspends until they are read, so
  render it under a Suspense boundary of your own; `getFormFields()` reads
  the values again.

## Form scripts

With `formScripts` as well as `forms`, the document's scripts run in its
fields as they do in pdf.js's viewer: calculated fields follow their
inputs, values are validated and formatted, keystrokes are checked as they
are typed, buttons run their actions, and the document and its pages run
their scripts as they open. The option is off by default, since the
scripts are the document's own JavaScript. They run in pdf.js's sandbox,
QuickJS compiled to WebAssembly, which loads only for a document that has
scripts: 66 KB of sandbox and 475 KB of QuickJS (20 KB and 220 KB with
gzip), served from the package's files like the worker's.

```tsx
<PdfViewer forms formScripts />
```

The viewers of one document share its sandbox, which keeps the fields'
values. What the scripts change reaches every viewer and the document's
values, and `useFormChange()` hears it; `setFormValues()` does not run
them. A script's request to turn the page, zoom, print, or save acts on the
viewer whose field ran it, and its alerts are the browser's own dialogs.

`WillSave`, `DidSave`, `WillPrint`, and `DidPrint` scripts do not run, and
XFA forms are not supported.
