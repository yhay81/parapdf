## Scroll modes

`viewer.setScrollMode(mode)`, or `PdfViewer`'s `scrollMode` (controlled,
with `onScrollModeChange`) or `defaultScrollMode`, arranges pages as pdf.js's
viewer does:

| Mode | |
|---|---|
| `"vertical"` | The default: pages stacked top to bottom. |
| `"horizontal"` | One row that scrolls sideways, centered in the viewport's height. |
| `"wrapped"` | Each row filled with as many pages as fit the viewport's width, again when it resizes. |
| `"page"` | One page, or one spread, at a time. |

In `"page"` mode, `goToPage()`, `nextPage()`, `previousPage()`, links, and
search turn pages, and so do the keys that would scroll past the edge of the
page shown: Page Down, space, and ↓ at its bottom and → at its right edge go
forward, and Page Up, Shift+space, ↑, and ← go back; Home and End go to the
first and last page.

On touch screens, a one-finger swipe to the left or up turns to the next
page, and to the right or down back, like turning paper. Short or slanted
swipes, pinches, and swipes with an annotation tool chosen do not. A zoomed
page scrolls within itself, and the pages beside it are drawn before they
show: a swipe from its edge turns it.

The current page stays in view when the mode changes.

## Spreads

`viewer.setSpread("odd")`, or the `spread` or `defaultSpread` prop, shows
pages side by side in pairs, 1–2, 3–4; `"even"` shows page 1 alone and pairs
2–3, 4–5, like a book with its cover; `"none"` goes back to one page per
row. Pairs stay together in every scroll mode: in a wrapped row and when
`"page"` mode turns.

## Right to left

Pages of a document read from the right, such as Japanese or Arabic books,
run right to left when the document says so in its `/ViewerPreferences
/Direction`, or when `PdfViewer`'s `direction` is `"rtl"`:

- the earlier page of a spread is on the right;
- rows of `"wrapped"` and the row of `"horizontal"` run right to left, and
  `"horizontal"` opens at its right end, on page 1;
- in `"page"` mode, ← goes forward and → back, and a swipe to the right
  turns to the next page; ↑, ↓, Page Up, Page Down, Home, and End do not
  change.

`direction="ltr"` keeps left to right whatever the document says. The view
state's `direction` holds the order shown. Page numbers, destinations,
search results, and `getViewState()` do not change with it.

## Fitting

`setScale("fit-width")`, or `"fit-width"` as `PdfViewer`'s `zoom` or
`defaultZoom`, the default, fits the current page to the viewport's width,
`"fit-page"` fits all of it, and `"auto"` fits as pdf.js's viewer opens
documents: the width of a portrait page and all of a landscape one, never
above a scale of 5/3 (pdf.js's 125%). All three keep fitting as the viewport resizes,
the view turns, or the page's real size arrives. The view state's
`zoomMode` says which one holds; a numeric scale, a zoom step, or a pinch
makes it `"custom"`, and `onZoomChange` then hears the scale.

In a spread mode, fitting counts two pages, so the zoom stays the same from
row to row, as in pdf.js. In `"horizontal"` mode, where all pages share one
row, fitting counts one.

Pages of different sizes are each centered in the viewport, and a page wider
than the viewport starts at its left edge.

## Presenting

ParaPDF has no presentation mode of its own, as pdf.js's viewer has: it is
the `"page"` scroll mode, `"fit-page"`, and the browser's Fullscreen API on
an element of your choosing, with the keys and controls you choose. This
one puts the viewer and a few controls full screen, shows the document a
page at a time while it stays there, and goes back to the scroll mode and
zoom from before, at the page the reader turned to, as pdf.js's viewer
does:

```tsx
"use client";

import { PdfDocument, PdfViewer, type ScrollMode, useViewer, type Viewer, type Zoom } from "parapdf";
import { useEffect, useRef, useState } from "react";

function usePresentation(viewer: Viewer) {
  const stage = useRef<HTMLDivElement>(null);
  const [presenting, setPresenting] = useState(false);
  useEffect(() => {
    let before: { scrollMode: ScrollMode; zoom: Zoom } | null = null;
    const onChange = () => {
      const now = document.fullscreenElement === stage.current;
      setPresenting(now);
      if (now && !before) {
        const { scrollMode, zoomMode, scale } = viewer.store.get();
        before = { scrollMode, zoom: zoomMode === "custom" ? scale : zoomMode };
        viewer.setScrollMode("page");
        viewer.setScale("fit-page");
        // The viewer's keys turn the pages while the viewport has focus.
        viewer.scroller?.focus({ preventScroll: true });
      } else if (!now && before) {
        viewer.setScrollMode(before.scrollMode);
        viewer.setScale(before.zoom);
        before = null;
      }
    };
    document.addEventListener("fullscreenchange", onChange);
    return () => document.removeEventListener("fullscreenchange", onChange);
  }, [viewer]);
  const present = () => void stage.current?.requestFullscreen();
  return { stage, presenting, present };
}

export function App() {
  const viewer = useViewer();
  const { stage, presenting, present } = usePresentation(viewer);
  return (
    <PdfDocument source="/slides.pdf">
      <button type="button" onClick={present}>Present</button>
      <div ref={stage} className="stage">
        <PdfViewer viewer={viewer} style={{ height: "100%" }} />
        {presenting ? (
          // A click leaves the focus in the viewport, whose keys turn the pages.
          <div
            role="toolbar"
            aria-label="Presentation"
            className="controls"
            onMouseDown={(event) => event.preventDefault()}
          >
            <button type="button" onClick={() => viewer.previousPage()}>Previous</button>
            <button type="button" onClick={() => viewer.nextPage()}>Next</button>
            <button type="button" onClick={() => void document.exitFullscreen()}>Exit</button>
          </div>
        ) : null}
      </div>
    </PdfDocument>
  );
}
```

```css
.stage { position: relative; height: 80vh; }
.stage:fullscreen { background: #000; }
.stage .controls { position: absolute; right: 16px; bottom: 16px; }
```

While it presents, the keys of `"page"` mode and swipes turn the pages,
Escape leaves full screen, and the buttons do what they say. A spread, a
rotation, and `direction` hold as they were. `document.fullscreenEnabled` is
false where an element cannot go full screen, as on the iPhone: hide the
button there.
