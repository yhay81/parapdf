With `<PdfViewer annotationEditing />`, the reader can create highlights,
text, drawings, images, and signatures, with pdf.js's editors.
`useAnnotations(viewer)` gives the editing state, the current tool and each
tool's style, with the methods below; it is null until the editor's code
loads, and without the option.

## Tools

`annotations.setTool(tool)` chooses what a pointer does on the pages:

| Tool | |
|---|---|
| `"highlight"` | Selecting text highlights it; a drag outside text highlights freehand. |
| `"freetext"` | A click adds text where the reader types. |
| `"ink"` | A drag draws. |
| `"stamp"`, `"signature"` | Select and move images and signatures, which `addImage()` and `addSignature()` add. |
| `"none"` | The default: annotations show, but cannot be selected. |

With any tool, the reader selects, moves, resizes, and deletes the
annotations created, and a selected one shows pdf.js's small toolbar with its
color and a delete button. Ctrl or ⌘ with Z undoes, and the arrow keys move
what is selected.

```tsx
import { useAnnotations, type Viewer } from "parapdf";

function AnnotationTools({ viewer }: { viewer: Viewer }) {
  const annotations = useAnnotations(viewer);
  if (!annotations) return null;
  const ink = annotations.styles?.ink;
  return (
    <div role="toolbar" aria-label="Annotations">
      <button
        type="button"
        aria-pressed={annotations.tool === "ink"}
        onClick={() => annotations.setTool("ink")}
      >
        Draw
      </button>
      <input
        type="color"
        aria-label="Line color"
        value={ink?.color.toLowerCase() ?? "#000000"}
        onChange={(event) => annotations.setStyle("ink", { color: event.target.value })}
      />
      <button type="button" disabled={!annotations.state?.canUndo} onClick={annotations.undo}>
        Undo
      </button>
    </div>
  );
}
```

## Styles, undo, and selection

- `setStyle(tool, style)` restyles the selected annotations, or, with none
  selected, the next ones `tool` creates: `color` for each tool, `thickness`
  for `"ink"` and freehand highlights, `opacity` for `"ink"`, and `fontSize`
  for `"freetext"`, in PDF points. `styles` shows each tool's style, or the
  selected annotation's.
- `undo()`, `redo()`, `deleteSelected()`, and `selectAll()`; `state` says
  whether there is something to undo or redo (`canUndo`, `canRedo`), whether
  annotations are selected (`hasSelection`), and whether there are any
  (`isEmpty`). `state` and `styles` are null until editing starts.

## Images and signatures

- `addImage(image, { pageIndex, altText })` adds an image, a `Blob` or a URL,
  to the current page or `pageIndex`, in the middle of its visible part, and
  selects it. `altText` describes it to assistive technology, in the saved
  PDF too.
- `addSignature(signature, { pageIndex, description })` adds a signature the
  same way, from typed text (`{ text, fontFamily }`, italic serif by
  default), an image (`{ image }`, whose outline is traced), or strokes the
  application drew (`{ strokes, width, height, thickness }`, each stroke a
  list of x and y coordinates in a box of `width` by `height`). ParaPDF shows
  no signature pad or dialog of its own.

Both resolve to `true` once the annotation is ready to save or export, or
`false` if it cannot be added. Await them before saving: an image's download,
decoding, or signature tracing may take time. Choosing another annotation
tool while either is pending cancels that insertion, which resolves to
`false`. Empty or untraceable signatures also resolve to `false`, without
adding an annotation or undo step.

## Annotations the PDF holds

The annotations a PDF already holds of the kinds the tools create (text,
drawings, highlights, and images) become editable while a tool is chosen:
they can be selected, moved, restyled, and deleted as those created, and a
double click on one with no tool chosen selects it. This needs the
`annotationLayer` option, which is on by default. Undo, unmounting, zoom,
and rotation keep the changes, and saving and printing write them.
Annotations of other kinds stay as they are drawn.

## Saving and keeping annotations

Annotations go into the document's bytes that `save(viewer)`,
`download(viewer)`, and `print(viewer)` use. To keep them apart from the
PDF, say on a server, `annotations.export()` returns them as
JSON-compatible data, and `annotations.import(saved)` adds them again where
they were, after the same document opens again, without an undo step, and
resolves to how many it added:

```ts
localStorage.setItem("annotations", JSON.stringify(annotations.export()));
// Later, once the document is open (status "ready"):
await annotations.import(JSON.parse(localStorage.getItem("annotations") ?? "[]"));
```

Each exported annotation has `pageIndex`, `type` (the tool that made it), and
`data`, pdf.js's own description of it: keep `data` as it is. It is the form
pdf.js pastes copies in, which may change when ParaPDF moves to another
pdf.js; the changelog says when. Text being typed counts once it is
committed, when the reader clicks elsewhere or another tool is chosen.
`export()` also includes the PDF's annotations the reader changed, not those
deleted, and `import()` puts each back in place of the annotation it
changed.

Annotations belong to the viewer that created them: they stay while its
`PdfViewer` unmounts and mounts again, and are gone once the component that
called `useViewer()` unmounts or `annotationEditing` turns off, so export or
save them before.

## Several viewers

Viewers of one `PdfDocument` that edit annotations share its document.
`save()`, `download()`, and `print()` from any of them include every
viewer's annotations, those of a viewer whose `PdfViewer` is unmounted too,
and what is being typed in any of them. Each viewer shows the annotations it
created. An annotation of the PDF one viewer changed or deleted is left out
by the others once they draw its page again, without the change, until that
viewer goes.

## Costs and limits

The editor's code and styles load only once `annotationEditing` is set, so
applications that do not edit annotations do not download them;
`useAnnotations()` is null until then. The option is live: setting it needs
no remount. `useAnnotationEditing(viewer)` gives the feature itself, whose
`store` reads its state as it is, without waiting for React to render. Thumbnails show
pages without the annotations created, as pdf.js's do.

Label the editor's controls in the application's language with
`annotationLabels`; the defaults are pdf.js's English names. New labels
apply without losing the annotations created.

Comments on created annotations are not shown.
