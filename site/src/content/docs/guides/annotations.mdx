With `<PdfAnnotationEditor />` mounted inside `<PdfViewer>`, the reader can
create highlights, text, drawings, images, and signatures, with pdf.js's
editors. `useAnnotations(viewer?)` gives the editing state, the current tool,
and each tool's style, with the methods below, tracking which fields the
component reads; `state` and `styles` are null until editing starts.

## Tools

`annotations.setTool(tool)` chooses what a pointer does on the pages:

| Tool | |
|---|---|
| `"highlight"` | Selecting text highlights it; a drag outside text highlights freehand. |
| `"freetext"` | A click adds text where the reader types. |
| `"ink"` | A drag draws. |
| `"stamp"`, `"signature"` | Select and move images and signatures, which `addImage()` and `addSignature()` add. |
| `"none"` | The default: annotations show, but cannot be selected. |

With any tool, the reader selects, moves, resizes, and deletes the
annotations created, and a selected one shows pdf.js's small toolbar with its
color and a delete button. Ctrl or ⌘ with Z undoes, and the arrow keys move
what is selected.

```tsx
import { PdfAnnotationEditor, PdfDocument, PdfViewer, useAnnotations } from "parapdf";

function AnnotationTools() {
  const annotations = useAnnotations();
  const ready = annotations.state !== null;
  const ink = annotations.styles?.ink;
  return (
    <div role="toolbar" aria-label="Annotations">
      <button
        type="button"
        disabled={!ready}
        aria-pressed={annotations.tool === "ink"}
        onClick={() => annotations.setTool("ink")}
      >
        Draw
      </button>
      <input
        type="color"
        aria-label="Line color"
        disabled={!ready}
        value={ink?.color.toLowerCase() ?? "#000000"}
        onChange={(event) => annotations.setStyle("ink", { color: event.target.value })}
      />
      <button type="button" disabled={!annotations.state?.canUndo} onClick={annotations.undo}>
        Undo
      </button>
    </div>
  );
}

export function AnnotatedReader() {
  return (
    <PdfDocument source="/manual.pdf">
      <AnnotationTools />
      <PdfViewer style={{ height: "80vh" }}>
        <PdfAnnotationEditor />
      </PdfViewer>
    </PdfDocument>
  );
}
```

`<PdfAnnotationEditor>` also accepts `tool`, `defaultTool`, and `onToolChange`
when the application controls or observes the active tool directly.

## Styles, undo, and selection

- `setStyle(tool, style)` restyles the selected annotations, or, with none
  selected, the next ones `tool` creates: `color` for each tool, `thickness`
  for `"ink"` and freehand highlights, `opacity` for `"ink"`, and `fontSize`
  for `"freetext"`, in PDF points. `styles` shows each tool's style, or the
  selected annotation's.
- `undo()`, `redo()`, `deleteSelected()`, and `selectAll()`; `state` says
  whether there is something to undo or redo (`canUndo`, `canRedo`), whether
  annotations are selected (`hasSelection`), whether there are any
  (`isEmpty`), and which one is selected when one alone is (`selected`).
  `state` and `styles` are null until editing starts.

## Comments and alternative text

`state.selected` describes the annotation selected, when one alone is: its
`id`, `pageIndex`, `type`, `comment` (null without one), and, for an image,
`altText` (`{ text, decorative }`). The application shows and edits them in
its own controls; ParaPDF shows no comment or alt text dialog.

- `setComment(comment)` sets the selected annotation's comment, or with
  null or `""` removes it. Text annotations take none: their text is their
  content.
- `setAltText({ text, decorative })` sets the selected image's alternative
  text; a decorative image is skipped by assistive technology.

Each is one undo step, and returns false unless one annotation alone, an
image for `setAltText()`, is selected. Typing in the application's own form
keeps the annotation selected. The saved PDF has the comment as the
annotation's popup note and the alternative text in its structure;
`export()` and `import()` keep both.

```tsx
function SelectedAnnotation() {
  const annotations = useAnnotations();
  const selected = annotations.state?.selected;
  if (!selected || selected.type === "freetext") return null;
  return (
    <form
      // Starts again when another annotation is selected, or undo changes it.
      key={JSON.stringify(selected)}
      aria-label="Comment"
      onSubmit={(event) => {
        event.preventDefault();
        const text = new FormData(event.currentTarget).get("comment");
        annotations.setComment(typeof text === "string" ? text : null);
      }}
    >
      <textarea name="comment" aria-label="Comment" defaultValue={selected.comment ?? ""} />
      <button type="submit">Apply</button>
      <button type="reset">Cancel</button>
    </form>
  );
}
```

## Images and signatures

- `addImage(image, { pageIndex, altText })` adds an image, a `Blob` or a URL,
  to the current page or `pageIndex`, in the middle of its visible part, and
  selects it. `altText` describes it to assistive technology, in the saved
  PDF too.
- `addSignature(signature, { pageIndex, description })` adds a signature the
  same way, from typed text (`{ text, fontFamily }`, italic serif by
  default), an image (`{ image }`, whose outline is traced), or strokes the
  application drew (`{ strokes, width, height, thickness }`, each stroke a
  list of x and y coordinates in a box of `width` by `height`). ParaPDF shows
  no signature pad or dialog of its own.

Both resolve to `true` once the annotation is ready to save or export, or
`false` if it cannot be added. Await them before saving: an image's download,
decoding, or signature tracing may take time. Choosing another annotation
tool while either is pending cancels that insertion, which resolves to
`false`. Empty or untraceable signatures also resolve to `false`, without
adding an annotation or undo step.

## Annotations the PDF holds

The annotations a PDF already holds of the kinds the tools create (text,
drawings, highlights, and images) become editable while a tool is chosen:
they can be selected, moved, restyled, and deleted as those created, and a
double click on one with no tool chosen selects it. This needs the
`annotationLayer` option, which is on by default. Undo, unmounting, zoom,
and rotation keep the changes, and saving and printing write them.
Annotations of other kinds stay as they are drawn.

## The file's comments

The comments the file already holds are its markup annotations that carry
one: a note's text, or another markup's popup note, such as a highlight's.
`useComments()` lists them across the pages, read once like the outline,
as `PdfComment`s: `id`, `pageIndex`, `rect` (PDF points from the page's
bottom left), `subtype` (`"Text"` for a note, `"Highlight"`, and so on),
`text`, `author`, `date` (when it was last changed, or else created), and
`replyTo`, the `id` of the comment it answers. A free text annotation's
text is what it shows, not a comment. The comments the editors add belong to
annotation editing (`useAnnotations()`).

```tsx
function Comments() {
  const comments = useComments();
  return (
    <ul>
      {comments.map((comment) => (
        <li key={comment.id}>
          p. {comment.pageIndex + 1}, {comment.author ?? "Anonymous"}: {comment.text}
        </li>
      ))}
    </ul>
  );
}
```

## Saving and keeping annotations

Annotations go into the document's bytes that `save(session)`,
`download(session)` (`useSave()`), and `print(viewer)` (`usePrint()`) use. To keep them apart from the
PDF, say on a server, `annotations.export()` returns them as
JSON-compatible data, and `annotations.import(saved)` adds them again where
they were, after the same document opens again, without an undo step, and
resolves to how many it added:

```ts
localStorage.setItem("annotations", JSON.stringify(annotations.export()));
// Later, once the document is open (status "ready"):
await annotations.import(JSON.parse(localStorage.getItem("annotations") ?? "[]"));
```

Each exported annotation has `pageIndex`, `type` (the tool that made it), and
`data`, pdf.js's own description of it: keep `data` as it is. It is the form
pdf.js pastes copies in, which may change when ParaPDF moves to another
pdf.js; the changelog says when. Text being typed counts once it is
committed, when the reader clicks elsewhere or another tool is chosen.
`export()` also includes the PDF's annotations the reader changed, not those
deleted, and `import()` puts each back in place of the annotation it
changed.

Annotations belong to the viewer that created them: they stay while its
`PdfViewer` unmounts and mounts again, and are gone once its owner
(`PdfDocument`, `PdfView`, or the component that called `useCreateViewer()`)
unmounts or `<PdfAnnotationEditor>` unmounts from an attached `PdfViewer`, so
export or save them before. They stay too while React hides the viewer or its
`PdfDocument` and keeps their state (`<Activity>`), and come back with the
same document and revision, including deletions of annotations originally
in the file. Saving and printing wait for images and other edits to finish
restoring. If the URL now serves a different PDF or revision, it opens with
its own annotations.

## Several viewers

Viewers of one `PdfDocument` that edit annotations share its document.
`save(session)`, `download(session)`, and `print(viewer)` include every
viewer's annotations, those of a viewer whose `PdfViewer` is unmounted too,
and what is being typed in any of them; those of a viewer React hides
(`<Activity>`) are left out until it is shown again. Each viewer shows the
annotations it created. An annotation of the PDF one viewer changed or deleted is left out
by the others once they draw its page again, without the change, until that
viewer goes.

## Costs and limits

The editor's code and styles are in your bundle only when you import
`PdfAnnotationEditor` (wrap it in `React.lazy()` if only some sessions edit
annotations). Mounting or unmounting `<PdfAnnotationEditor>` needs no remount
of `<PdfViewer>`. `useAnnotations(viewer?)` always returns an
`AnnotationControls` object (`state` and `styles` are null until editing
starts) and tracks read fields so components that read only methods (such as
`const { setTool } = useAnnotations()`) never re-render on annotation changes.
Thumbnails show pages without the
annotations created, as pdf.js's do.

Label the editor's controls in the application's language with
`PdfAnnotationEditor`'s `labels`; the defaults are pdf.js's English names. New
labels apply without losing the annotations created.
