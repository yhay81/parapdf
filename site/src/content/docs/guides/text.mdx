## The document's text

`getText(session, options)` reads the document's text from every page, mounted
or not, as search reads it: the text runs in content order, `"\n"` where a
line ends, and an empty line between pages.

```ts
const { text, pages } = await getText(session);
// pages: [{ pageIndex: 0, text: "…", offset: 0 }, …], where offset is the page's start in text
```

- `from` and `to` narrow it to pages (`{ from: 2, to: 4 }` reads pages 3 to
  5) or to points in the text: a search match's ends,
  `{ pageIndex: match.pageIndex, ...match.start }` and `...match.end`, or a
  selection's, `selection.start` and `selection.end`. A point is included
  as a start and excluded as an end.
- `lineBreaks: "join"` joins lines as search does: without a space inside a
  word hyphenated across lines and in Japanese and Chinese text, with one
  elsewhere.
- `signal` stops a read, which then rejects with the signal's reason.

Pages are parsed in pdf.js's worker a few at a time, and the text is kept: a
second read, or a search, parses nothing again. The browser's selection
covers only mounted pages; to copy a range longer than those, read it with
`getText()` between the points where it starts and ends.

## Selections and popovers

`useSelection(viewer?)` returns the text selected in the viewer, the rectangles
it covers in the PDF points `PdfPageRect` takes, and a virtual `anchor` whose
`getBoundingClientRect()` follows scroll, zoom, and rotation; null when nothing
is selected there. It follows the selection at most once a frame while the
reader drags:

```tsx
const selection = useSelection();
// { text: "…", pages: [{ pageIndex: 0, rects: [{ x, y, width, height }] }], start, end, anchor } or null
```

`start` and `end` are where the selection begins and ends in the document's
text, for `getText()`; null for an end outside the pages' text. `selection.anchor`
satisfies Floating UI, Radix Popover, and Base UI's virtual-reference contract.

Rectangles are in PDF points of the page unturned by the view, from its
top-left corner, so they stay right whatever the zoom and rotation.

To show floating actions (such as a copy or highlight toolbar) anchored to the
selection without clipping at a page's `contain: "strict"` boundary or
committing React state on scroll, render `PdfSelectionPopover` inside
`PdfViewer`:

```tsx
<PdfSelectionPopover placement="top" offset={8}>
  {(selection) => (
    <button type="button" onClick={() => navigator.clipboard.writeText(selection.text)}>
      Copy
    </button>
  )}
</PdfSelectionPopover>
```

Pressing non-editable buttons inside `PdfSelectionPopover` keeps the browser's
text selection intact until your `onClick` handler clears or acts on it.

## Overlays and page coordinates

`PdfPageOverlay` and `PdfPageOverlays` draw your own elements over pages, placed
with `PdfPageRect` in PDF points from the page's unturned top-left corner. React
renders them through a portal into a layer of the page, above its drawing and
text, and they follow zoom and rotation through layout alone, without
re-rendering:

```tsx
<PdfViewer
  style={{ height: "100vh" }}
  onPageClick={({ pageIndex, x, y }) => {
    // Clicked coordinates are in the same unturned PDF points PdfPageRect takes.
  }}
>
  <PdfPageOverlay page={0}>
    <PdfPageRect x={72} y={72} width={200} height={24}>
      <mark style={{ display: "block", height: "100%", opacity: 0.4 }} />
    </PdfPageRect>
  </PdfPageOverlay>
  <PdfPageOverlays>
    {(pageIndex) =>
      pinsByPage.get(pageIndex)?.map((pin) => (
        <PdfPageRect key={pin.id} x={pin.x} y={pin.y} width={16} height={16}>
          <PinMarker pin={pin} />
        </PdfPageRect>
      ))
    }
  </PdfPageOverlays>
</PdfViewer>
```

- `PdfPageOverlay` takes a zero-based `page` prop and plain `children` (no
  function prop), so Server Components can pass streamed JSX directly through it
  while unmounted pages mount nothing.
- `PdfPageOverlays` evaluates `children(pageIndex)` inside each mounted page's
  memoized subtree, so scrolling the mounted window never re-evaluates overlays
  on pages that stay mounted.
- `PdfPageRect` forwards `ref` and `className` to its positioned element for
  anchoring tooltips or popovers.
- `PdfViewer`'s `onPageClick(point, event)` and `viewer.pointAt(event)` map
  client coordinates to `{ pageIndex, x, y }` in the same unturned PDF points
  across view rotations (`0`, `90`, `180`, `270`), zoom previews, and `/UserUnit`
  pages (`null` in gaps or outside the viewport).
