`PdfThumbnails` lists the pages of a viewer's document as buttons, each with
a thumbnail and the page's number, marks the current page, and goes to a
page when the reader chooses it:

```tsx
import { PdfDocument, PdfThumbnails, PdfViewer, useViewer } from "parapdf";

function Reader() {
  const viewer = useViewer();
  return (
    <PdfDocument source="/manual.pdf">
      <PdfThumbnails viewer={viewer} width={120} style={{ overflow: "auto" }} />
      <PdfViewer viewer={viewer} />
    </PdfDocument>
  );
}
```

`onSelect(pageIndex)` replaces going to the page; `label` names the list
and `pageLabel(pageNumber, pageCount)` each button, in the application's
language. Thumbnails follow the viewer's rotation and draw with its drawing
slots, so they need the viewer whose pages they list.

For a list of your own, `PdfThumbnail` (`viewer`, `pageIndex`, `width`) draws
one page `width` CSS pixels wide; its height follows the page's shape as the
view turns it. It is a picture only: wrap it in a button or a link labelled
with the page.

## What it costs

- Only thumbnails near the visible part of their scroll container hold
  pixels, so a list of every page stays cheap: one `IntersectionObserver`
  per container draws those that come near and clears the others.
- Thumbnails draw at a lower priority than the pages in view, and always
  leave a render slot for the next page that scrolls in.
- A thumbnail copies the page's drawing when the viewer already has one at
  least as large, instead of drawing the page again.

Thumbnails show pages without the annotations the reader created, as
pdf.js's do, and pages drawn with fillable forms are drawn again for them.
