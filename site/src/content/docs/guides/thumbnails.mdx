`PdfThumbnails` lists the pages of a viewer's document as a window-virtualized
navigation list of buttons, each with a thumbnail and the page's label (from the
PDF's `pageLabels` once read, without suspending, or its one-based number),
marks and scrolls the current page into view, and goes to a page when the reader
chooses it:

```tsx
import { PdfDocument, PdfThumbnails, PdfViewer } from "parapdf";

function Reader() {
  return (
    <PdfDocument source="/manual.pdf">
      <PdfThumbnails width={120} style={{ overflow: "auto" }} />
      <PdfViewer />
    </PdfDocument>
  );
}
```

`onSelect(pageIndex)` replaces going to the page; `label` names the list and
`pageLabel(pageNumber, pageCount, label)` each button, in the application's
language (`"Page iv"` when the PDF defines custom page labels, or
`"Page 3 of 12"` otherwise). Pass `children` (`(item: ThumbnailItem) => ReactNode`)
to customize each mounted `<li>`'s contents while keeping window virtualization,
automatic page labels, and current-page auto-scrolling. Thumbnails follow the
viewer's rotation and draw with its drawing slots: by default they read the
nearest `PdfView` or `PdfDocument`'s viewer, or take an explicit `viewer` prop.

For a list of your own, `PdfThumbnail` (`pageIndex`, `width`, optional
`viewer`) draws one page `width` CSS pixels wide; its height follows the
page's shape as the view turns it. It is a picture only: wrap it in a button
or a link labelled with the page.

## What it costs

- Only items near the visible part of their scroll container mount in the DOM
  and hold pixels, so a 1,000-page document mounts ~20 `<li>` elements instead
  of 1,000 while keeping exact scroll height and `aria-setsize` /
  `aria-posinset` semantics.
- Thumbnails draw at a lower priority than the pages in view, and always
  leave a render slot for the next page that scrolls in.
- A thumbnail copies the page's drawing when the viewer already has one at
  least as large, instead of drawing the page again.

Thumbnails show pages without the annotations the reader created, as
pdf.js's do, and pages drawn with fillable forms are drawn again for them.
