# Contributing to ParaPDF

ParaPDF is at 0.x and has one maintainer, so small, focused pull requests are
reviewed soonest. For a new feature or a change to the API, open an issue
first: it may not fit what ParaPDF is for, or it may need a measurement
before code.

[`AGENTS.md`](AGENTS.md) is the full development context: the layout of the
repository, every command, and how the benchmarks measure.
[`docs/rebuild/target.md`](docs/rebuild/target.md) describes how the runtime
is built, and [`docs/decisions/`](docs/decisions) records why, with the
measurements. This file is the short version for people.

## What ParaPDF is for

- **React-first.** The runtime is designed around React semantics, and
  React stays out of the hot path: scrolling and zooming commit no React
  state per frame, pixels never go through React state, and drawing leaves
  the main thread wherever pdf.js allows it.
- **pdf.js through its core display API.** pdf.js is the only engine, used
  directly, with no engine abstraction: `getDocument`, page rendering,
  `TextLayer`, and `AnnotationLayer`; not the viewer components in
  `pdfjs-dist/web/`. ParaPDF does not fork or patch pdf.js: changes it needs
  go upstream. Code ported from pdf.js's viewer needs Apache-2.0
  attribution in [`NOTICE.md`](NOTICE.md) and in the file.
- **Domain-neutral.** ParaPDF shows PDFs as documents: reading, search,
  selection, links, annotations, and forms. Scales, real-world lengths,
  measuring tools, and CAD layers belong in libraries built on a PDF engine.
- **Measured.** A performance claim comes with its measurement, and the
  numbers that got worse are published with those that got better.

## Setting up

You need Node 24 or later and pnpm 12, the version `packageManager` in
[`package.json`](package.json) names.

```bash
pnpm install
pnpm --filter @parapdf/bench exec playwright install chromium webkit firefox
pnpm --filter @parapdf/bench corpus
pnpm --filter @parapdf/prototype dev
```

The last command runs the demo. Its query parameters, which choose the file,
scroll mode, zoom, and more, are read in
[`examples/prototype/src/App.tsx`](examples/prototype/src/App.tsx).

## Before you open a pull request

```bash
pnpm check
pnpm --filter parapdf --filter @parapdf/prototype --filter @parapdf/site typecheck
pnpm test
pnpm --filter parapdf check:package
pnpm --filter @parapdf/prototype build
ENGINE=pdfjs pnpm --filter @parapdf/prototype check:text
```

- Run the functional checks your change touches; `AGENTS.md` says what each
  one covers. `ENGINE=pdfjs` runs them on the pdfjs-dist the package ships.
  CI runs every one in Chromium, WebKit, and Firefox on Linux; when one
  fails there, the job's `diagnostics-<browser>` artifact holds the browser's
  console and screenshots of the failure. For selection, gestures,
  scrolling, or layout, run them with `BROWSER=webkit` and
  `BROWSER=firefox` on your machine too: CI's browsers run on Linux without
  a GPU, and Playwright's WebKit is not Safari.
- A change to the package gets an entry under "Unreleased" in
  [`CHANGELOG.md`](CHANGELOG.md), and both
  [`packages/parapdf/README.md`](packages/parapdf/README.md), the package's
  documentation on npm, and the documentation site in [`site/`](site)
  follow the API. `pnpm --filter @parapdf/site dev` shows the site.
- Measure performance with the benchmarks described under "Benchmark
  methodology" in `AGENTS.md`, on AC power.
- Write code, comments, documentation, and commit messages in English;
  Japanese belongs only in localized documentation and CJK test data.
  Commit subjects are imperative sentences without a prefix, as in
  `git log`.

## Test documents

A PDF added to [`bench/corpus/`](bench/corpus/README.md) needs a
redistributable license, a source documented in its README, and coverage the
corpus does not have yet. Stress documents are generated by
`bench/scripts/gen-synthetic.ts` and never committed.

Issues and pull requests are public: attach a PDF only if it may be shared.

## Reporting problems

Use the issue forms. Security problems go through [`SECURITY.md`](SECURITY.md)
instead. If pdf.js's own viewer shows the same problem, it may belong to
pdf.js; the bug report asks about that.
